# 流转与审批 V1 · 升级清单

适用：老板和员工之间在同一个项目上来回流转（派单、接收、拒绝、交回、退回返工），以及员工的敏感操作先申请、老板批准后才生效。代码在 `feat/flow-v1` 分支（backend、admin 两个仓库；客户端 app 没有改动）。

> **从旧版一次升到最新**：直接按 [上线手册.md](上线手册.md) 做，它已经包含这份清单的数据库步骤。
> **线上已经是记单收款版本（`feat/solo-v1`）**：只需要照这份清单做。

## 这一版改了什么

### 一、项目在老板和员工之间流转

1. **派单后员工要“接收”**：老板把项目派给员工（新建时选负责人、改派、卡片上点“派给”），项目会带上“等 TA 接收”的标记，员工在工作台和项目详情里点「接收」后才能开工；老板自己名下的项目、客户提交的项目不需要接收。
2. **员工“拒绝”**：刚派来、还没接收的项目，员工可以拒绝，必须写原因；项目回到老板名下。
3. **员工“交回老板”**：做到一半做不了，员工可以把项目交回，必须写原因；项目回到老板名下并变成“待确认”（交回后员工就看不到它了）。已完成、已取消的项目不能交回。
4. **老板“退回返工”**：验收不满意（项目在“待验收”或“已完成”），老板点「退回返工」，必须写原因；项目回到“进行中”，改稿次数 +1，负责人收到通知。
5. 每一步都会在项目时间线里留一条记录（谁、做了什么、原因），在操作日志里留痕，并给对方出红点和（配了微信推送时）推送。

### 二、员工的敏感操作先申请，老板批准才生效

| 员工想做的事 | 现在怎么办 |
|---|---|
| 改报价 | 在项目详情里点“申请改价”（或“申请…→改报价”），写新报价和原因 |
| 取消项目 | “申请…→取消项目” |
| 删除项目 | “申请…→删除项目”（批准后进回收站，可恢复） |
| 收款 | 记收款窗口变成“申请收款”，老板确认后才计入已收和实收 |
| 标已完成 | 不能直接标，点“提交验收”，由老板验收通过 |

- 老板在工作台的“待我批准”里一条条处理：批准（立刻按申请内容执行）或驳回（必须写原因）；员工在“我的申请”里看结果，可以撤回还没处理的申请。
- 同一个项目的改报价 / 取消 / 删除，同一时间只能有一条待批；收款可以分几笔分别申请。
- 老板自己操作一切照旧，不需要申请。
- 后端同时设了闸门：即使有人绕过页面直接调接口，员工也改不了报价、取消、删除、记收款、标已完成。

## 升级步骤

线上已是记单收款版本时：

```bash
# 1. 备份（必须）
mysqldump --defaults-extra-file=/opt/xuancheng-order/config/mysql-root.cnf \
  --single-transaction xc_jiedan \
  > /opt/xuancheng-order/backups/xc_jiedan_before_flow_v1_$(date +%F_%H%M).sql

# 2. 升级数据库（只新增字段和表，可重复执行，旧版后端不受影响）
M="mysql --defaults-extra-file=/opt/xuancheng-order/config/mysql-root.cnf --default-character-set=utf8mb4"
$M xc_jiedan < upgrade_approval_v1.sql
$M xc_jiedan -e "show tables like 'jiedan_approval'; show columns from jiedan_order like 'assign_state'; select count(*) as 等接收的项目 from jiedan_order where assign_state <> ''"
```

3. 放入新版本目录、切换 `current`、重启后端——和上线手册第六步完全一样。
4. 浏览器 Ctrl+F5 强刷一次后台页面。

升级后已有的项目都是“无需接收”，不会突然出现等接收的标记；员工从升级那一刻起，改报价、取消、删除、收款都要走申请。**请在升级前告诉员工这个变化。**

## 验收

用老板账号和一个员工账号各走一遍：

**流转**
- [ ] 老板新建项目选负责人=员工 → 员工工作台出现“老板派给你的新项目”，有「接收」「拒绝…」；接收前员工点不了“开始做”。
- [ ] 员工点「接收」→ 项目恢复正常，老板那边时间线有“接收了这个项目”。
- [ ] 老板再派一个，员工点「拒绝…」写原因 → 项目回到老板名下（“待确认”），老板看到原因。
- [ ] 员工在一个进行中的项目里点「交回老板…」写原因 → 员工的列表里没有这个项目了，老板那边是“待确认”，有原因。
- [ ] 员工提交验收 → 老板在项目里点「退回返工…」写原因 → 项目回到“进行中”，改稿次数 +1，员工看到原因。
- [ ] 老板点“验收通过”→ 项目已完成。

**申请**
- [ ] 员工在项目详情点“申请改价”，写新报价和原因 → 老板工作台“待我批准”出现这条；员工那边项目报价没变。
- [ ] 老板点“批准” → 报价变了；员工的“我的申请”里显示“已批准”。
- [ ] 员工再申请一次，老板点“驳回…”写原因 → 报价不变，员工看到驳回原因。
- [ ] 员工申请取消 / 删除，老板批准 → 项目被取消 / 进回收站。
- [ ] 员工点“申请收款”填金额 → 老板批准后才计入已收；数据站“本月实收”才增加；收款记录里记录人是员工的名字。
- [ ] 员工在列表里找不到“完成”（只有“提交验收”），在“设为…”里没有“已完成 / 已取消”，也没有直接的“删除”。
- [ ] 操作日志里能看到：接收、拒绝、交回、退回返工、提交申请、批准申请、驳回申请、撤回申请。

## 回滚

- **只做了数据库**：不用回滚，新字段和新表旧版后端用不到。
- **已经切换版本，要退回记单收款版**：把 `current` 切回旧版本目录并重启后端即可。
  - 申请表里没处理的申请，旧版看不到也不会执行，它们不会生效，也不会丢；
  - 旧版没有“接收”这一步，等接收的项目退回旧版后员工可以直接开工；
  - 旧版里员工又能直接改报价、取消、删除、记收款。

## 已知限制

- “老板”指总管理员；员工交回、拒绝时，项目回到系统里排在第一位的总管理员名下。
- 员工被停用或删除时，他还没处理完的申请不会自动清理，老板可以直接批准或驳回。
- 批准一条申请时，如果项目已经被删除或状态已经不允许（比如已经取消了），批准会失败并提示原因，申请保持“待批”，老板可以驳回它。
- 延期（改截止日期）暂时不需要申请，员工可以直接改。
- 微信推送没配 SendKey 时，所有“有新申请 / 被批准 / 被驳回 / 被派单”的提醒只有页面红点，没有微信消息。
